# Profiles and discovery

Identity accepts authenticated `POST /api/v1/me/avatar` with a raw JPEG, PNG or WebP body (matching Content-Type), maximum 5 MB. Decoded images must be single-frame and at most 20 megapixels. It applies orientation, strips metadata and resizes within 512 × 512 before encoding WebP. `DELETE /api/v1/me/avatar` removes the photo. The public user includes nullable `avatarUrl` and `homeCity`. `PATCH /api/v1/me` accepts name and optional nullable homeCity; email and sign-in identities remain read-only.

The local MinIO image is built from the pinned [source release](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z) because published registry images are unavailable. MinIO stores local avatars in the dedicated `avatar-data` volume. Identity replicas use the same bucket and database. Configure AVATAR_S3_ENDPOINT, AVATAR_S3_BUCKET, AVATAR_S3_ACCESS_KEY and AVATAR_S3_SECRET_KEY for production S3-compatible storage. Back up the bucket **and** the Identity database together; restore objects before serving restored metadata. Upload failures leave the previous photo intact. Failed old-object deletion can leave an unreferenced object: periodically reconcile bucket objects against tc_account.avatar_key with a grace period to protect in-flight uploads. Avatar images are public and immutable at random URLs.

The shared package owns the curated 30-city allowlist, categories, languages and age policies. Browsing city is saved in localStorage. An explicit selection, including All cities, overrides homeCity. Without a saved selection, discovery uses homeCity.

Event save accepts performers, venueAddress, entryAt (UTC), languages, agePolicy, accessibilityNotes and tier inclusions. Drafts may omit publication facts; publishing requires description, address, language and an age policy, plus performers for music categories. Legacy facts remain nullable and are displayed as unspecified. Only deterministic seed IDs receive fictional demonstration facts. Dates entered in the editor use the selected event timezone. DST gaps and overlaps are rejected. Entry may be within the preceding 24 hours. Dates and sold prices retain existing freeze rules.

Prices are entered as decimal rupees and converted exactly to integer paise. APIs, order snapshots and storage remain in paise. Omitted saved tiers without purchase/allocation history are deleted; tiers with history become retired. Existing holds and admissions survive retirement. New reservations and expired-order reallocation cannot use retired tiers. Retired tiers appear only in organizer history and are excluded from Catalog projections.

Migration 20261001010000_discovery_profiles is additive. Compose startup deploys it to the preserved source database and applies service-owned columns idempotently through bootstrap. Never reset volumes or edit old migrations. Search projections can be refreshed with `docker compose exec catalog node apps/api/dist/scripts/rebuild-search.js`.

Browser fixtures mark new events with `browser:<unique-id>` and cancel captured IDs in a finally block, even after journey failures. The specifically identified historical test listing is cancelled by the focused cleanup script, preserving orders and using the ordinary refund workflow.
