# UI review — October 1, 2026

The running application at http://localhost:8080 was reviewed in a real Chromium browser, with screenshots, keyboard interaction, accessibility scans and purchase/organizer journeys. The review covers home, discovery, empty search results, event details, sign-in, registration, missing pages, profile, organizer dashboard/editor, tickets and checkout. Desktop, tablet, mobile and 320-pixel layouts are included.

## Verification

The final visual audit captured 50 page/viewport combinations at 1440, 768, 390 and 320 pixels. No horizontal overflow, page-level JavaScript errors, broken images or violations of the scanned WCAG rules were found. Screenshots were also inspected directly; this exposed the microphone framing issue that automated scans did not detect.

The final verification passed 20 desktop/mobile browser scenarios, 49 isolated integration tests (one skipped), 14 unit tests and six replicated service journeys. Builds, type checks, lint and formatting passed. Containers were rebuilt and relaunched; the existing database identifiers and inventory invariants were preserved. Browser-created events are marked and cancelled in fixture cleanup.

The browser regression suite exercises keyboard skip navigation, image fallback, sticky/bottom booking controls, filter synchronization, artist search, and profile/photo/editor save failures. It checks that entered values remain available after failures, ambiguous local times receive actionable feedback, and private forms fit a 320-pixel viewport. Existing desktop/mobile journeys cover avatar upload/removal, city persistence, publication, tier removal/retirement, purchase/refund and check-in.

Accessibility scans use axe's WCAG 2 A/AA and 2.1 A/AA rules. They complement visual inspection and keyboard checks; they do not establish complete accessibility certification. Live third-party consent, physical camera behavior and real device wallet signing remain outside this local review.

Screenshots and the page-by-page JSON audit are saved under `artifacts/ui-review/`. Representative captures are [desktop event details](../artifacts/ui-review/desktop-dark-details.png), [mobile booking](../artifacts/ui-review/mobile-dark-sticky-booking.png) and [320-pixel editor](../artifacts/ui-review/mobile-dark-editor-320.png). Playwright attaches accessibility results to its HTML report. The source checks and service layout are documented in [validation evidence](VALIDATION.md) and [service code layout](service-layout.md).

## Remaining observations

The narrow layout keeps event facts readable and the booking action reachable without horizontal scrolling. The 320-pixel organizer form is long but grouped by responsibility. Discovery uses consistent poster proportions and visible dates, venues and rupee prices. Legacy metadata remains explicitly unspecified. Organizer-provided artwork and listings were preserved; events were not changed solely because their names resembled test data.

The production build still reports large JavaScript chunks: approximately 626 kB for the application, 705 kB for Three.js and 1,161 kB for the optional wallet bundle before compression. The Three.js and wallet bundles load through dynamic imports. Further loading/bundle optimization is a separate improvement; these build sizes are not measurements of performance on a slow mobile network.
